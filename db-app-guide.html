Créer une application web avec base de données

Front, backend et base de données centralisée, hébergés en ligne — étape par étape. Suis le déroulé, coche chaque étape, copie les prompts.

# hébergé en ligne # accessible par URL # ~1h en autonomie # Git · CI/CD · Azure/AWS · Claude Code

Astuce : déroule la page de haut en bas. Clique sur les numéros pour cocher les étapes validées et sur copier pour récupérer un prompt. Le sélecteur de langue est en haut à droite.

Le concept

Cinq maillons, une app en ligne

Une application web avec base de données ajoute deux briques à la version locale : un déploiement automatisé et un hébergeur qui fait tourner l'app et la base en permanence.

Idée → Claude (IA) → Repo Git → Build & déploiement → Hébergeur web + base de données
Brique 1

Claude écrit l'app complète

À partir d'une idée en langage naturel, Claude génère le frontend, le backend (API) et le schéma de base de données (tables, migrations).

Brique 3

L'hébergeur fait tourner l'ensemble

L'app et sa base de données centralisée tournent en permanence chez un hébergeur, accessibles par une URL publique — disponibles pour tous, tout le temps.

Étape 1 — Préparer

Préparer ton environnement

À faire une seule fois. Comptez 20 min, y compris la création des comptes hébergeur.
0/6 étapes
1

Tester Claude + créer un GitHub

Connecte-toi à Claude (compte Wavestone) et crée un compte GitHub gratuit pour stocker et versionner ton code.
claude.ai/new ↗github.com ↗
2

Installer Git, GitHub Desktop, VS Code

Les trois outils de base : Git suit les modifications, GitHub Desktop synchronise ton repo avec ta machine, VS Code est l'éditeur où tu travailleras. Aucun droit admin requis.
git-scm.com ↗desktop.github.com ↗code.visualstudio.com ↗
3

Extension Claude Code

Dans VS Code : Extensions (Ctrl+Shift+X) → cherche « Claude Code » (Anthropic) → Installer. Connecte ton compte Claude et ouvre un dossier de ta machine.
guide officiel ↗
4

Choisir un hébergeur web + base de données

Pour un périmètre Wavestone maîtrisé, privilégie Microsoft Azure (App Service + Azure Database) — voir la note de gouvernance ci-dessous. Demande à Claude de te recommander la formule la plus simple pour ton cas d'usage.
5

Créer une base de données vide

Crée une instance de base de données managée chez ton hébergeur (ex : Azure Database for PostgreSQL). Récupère la chaîne de connexion — tu en auras besoin à l'étape de déploiement.
6

Prévoir la gestion des secrets important

La chaîne de connexion et les clés API ne doivent jamais apparaître dans le code commité. Elles se configurent en variables d'environnement, côté hébergeur ou en secrets GitHub Actions.
Étape 2 — Construire

Construire ton app avec Claude

Ouvre un dossier dans VS Code, puis demande à Claude Code de créer ton application. Voici deux prompts pour démarrer :

Exemple — app avec formulaire & base de données
Crée-moi une application web avec un formulaire de contact : un frontend simple, une API backend qui enregistre chaque soumission dans une base de données PostgreSQL, et un script de migration pour créer la table.
Exemple — page d'administration
Ajoute une page d'administration qui liste toutes les entrées de la base de données, protégée par une authentification simple par mot de passe.
Human in the loop

Claude te propose les commandes avant de les exécuter : lis ce qu'il propose, puis valide. Pour du code qui touche à une base de données, relis particulièrement les migrations avant de les valider.

Données de test uniquement

Ne mets aucune donnée client réelle ni information confidentielle dans une base de données de démonstration ou de POC. Utilise des données fictives.

Étape 3 — Déployer

Mettre l'app en ligne

Une fois le code prêt, connecte-le à ton hébergeur pour qu'il tourne en continu.
0/5 étapes
1

Pousser le code sur GitHub

Avec GitHub Desktop ou git push, envoie ton repo sur GitHub. C'est la source unique de vérité que l'hébergeur ira lire.
2

Connecter le repo à l'hébergeur

Dans la console de ton hébergeur (ex : Azure App Service), lie ton repo GitHub : un pipeline de build & déploiement se met en place automatiquement à chaque push sur la branche principale.
3

Renseigner les variables d'environnement

Dans les paramètres de l'hébergeur (jamais dans le code) : colle la chaîne de connexion à la base de données et les éventuelles clés API.
4

Lancer le premier déploiement

Déclenche le build et surveille les logs. En cas d'erreur, copie le message et demande à Claude de t'aider à le corriger.
5

Initialiser le schéma en production

Exécute le script de migration sur la base de production pour créer les tables, puis vérifie que l'app répond bien à son URL publique.
Gouvernance Wavestone — Hébergement en ligne

Pour les données clients sensibles, deux options internes sont disponibles :

• Microsoft Azure recommandé — App Service + Azure Database (SQL/PostgreSQL), intégré à l'écosystème Wavestone.

• Amazon Web Services (AWS) — alternative disponible pour certains scénarios (RDS, Elastic Beanstalk). À valider avec la gouvernance IT.

Dans les deux cas, une clé API Wavestone permet de rester dans un périmètre sécurisé et tracé.

Aller plus loin

Une app en ligne, à toi de la faire vivre

Une fois la boucle maîtrisée, chaque nouvelle fonctionnalité suit le même chemin : idée, prompt, push, déploiement automatique.

Bloqué ? Demande à l'IA

Erreur de déploiement, migration qui échoue, variable d'environnement manquante : colle le message d'erreur à Claude, il t'aide à diagnostiquer.

Sécurise ta base de données

Avant d'ouvrir l'app à d'autres : demande un audit de sécurité, vérifie que la base n'est pas accessible publiquement sans authentification, et que les secrets ne sont pas dans le code.

La boucle ne change pas

Idée → prompt → push → déploiement automatique → itération. Ce rythme, tu le connais désormais.
