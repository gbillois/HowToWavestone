VS Code est l’éditeur dans lequel tu installeras ensuite Claude Code.

  1. Ouvre la page officielle : https://code.visualstudio.com/download.
  2. Télécharge l’installateur Windows (User ou System Installer : le User Installer convient dans la plupart des cas).
  3. Lance le .exe, accepte la licence, laisse les options par défaut (case « Add to PATH » cochée si proposée), puis Install / Finish.
  4. Validation : ouvre VS Code depuis le menu Démarrer : la fenêtre s’affiche sans erreur bloquante.
Tip

Pas de portail d’applications interne ici : on passe uniquement par le site officiel Microsoft.

1 / 10

Git sert à versionner ton agent. On reste sur la ligne de commande (pas besoin de client graphique).

  1. Télécharge / installe depuis https://git-scm.com/install/ (choisis Windows, suis l’installateur, options par défaut OK).
  2. Ouvre un terminal Windows pour configurer Git avant (ou sans) VS Code : Win+R puis tape cmd + Entrée, ou menu Démarrer → « Terminal » / Windows Terminal. Autre raccourci courant : Win+X puis Terminal.
  3. Une fois VS Code installé, tu pourras aussi ouvrir un terminal dedans : menu Terminal → New Terminal, ou raccourci Ctrl+` (touche accent grave ; sur clavier FR AZERTY, souvent Ctrl+ù selon le mapping).
  4. Identité Git globale (git config --global) = pour tous les repos de la machine. Tape : 
    git config --global user.name "Prénom Nom"
git config --global user.email "prenom.nom@wavestone.com"
  5. Identité locale (sans --global, dans un dépôt déjà initialisé) = seulement ce repo, et écrase le global pour ce dépôt : 
    git config user.name "Prénom Nom"
git config user.email "prenom.nom@wavestone.com"
  6. Vérifie : git config --global --list (global) ou git config --list (effectif dans le dossier courant).
  7. Validation : git --version affiche un numéro de version.
Tip

Pour cette étape, privilégie le Terminal Windows (cmd / Windows Terminal). Une fois VS Code installé, tu pourras aussi utiliser son terminal intégré.

1 / 24

L’extension Claude Code dans VS Code te servira à générer et itérer sur ton agent HTML.

  1. Dans VS Code, ouvre l’onglet Extensions (icône carrés dans la barre latérale, ou Ctrl+Shift+X).
  2. Cherche Claude Code.
  3. Clique Install sur l’extension officielle.
  4. Validation : l’extension apparaît dans la liste des extensions installées (icône / entrée Claude visible).
Important

La connexion des comptes / licences se fait à l’étape macro suivante (Macro 02 : licences). Ici, on installe seulement l’extension.

1 / 4

Check rapide avant de passer aux licences d’entreprise.

  1. VS Code s’ouvre sans alerte bloquante.
  2. git --version répond dans un terminal Windows (ou VS Code si tu l’utilises déjà).
  3. L’extension Claude Code est installée (la connexion compte / licence vient au Macro 02).
OK

Si les trois points sont verts, passe au Macro 02 (licences d’entreprise).

Tu as installé l’extension en Macro 01 : ici, tu demandes la licence entreprise via le lanceur d’applications Microsoft 365, puis tu connectes ton compte dans VS Code.

Accès direct à la demande : Request Center SailPoint. Sinon, suis le chemin ci-dessous depuis le lanceur d’applications.

  1. Ouvre le lanceur d’applications (la grille en haut à gauche) depuis l’intranet / SharePoint.
  2. Choisis Plus d’applications, puis All apps.
  3. Descends dans la liste jusqu’à SailPoint (section Other Apps) et ouvre-le.
  4. Sur le tableau de bord, ferme la visite guidée si elle s’affiche (No thanks).
  5. Ouvre Request Center, puis New Request.
  6. Choisis Request for Myself. Ferme la visite du Request Center si elle apparaît.
  7. Dans Access Items, cherche Claude AI standard et sélectionne Anthropic - Claude AI standard usage.
  8. Renseigne la date de fin (l’écran indique 6 mois maximum), le fuseau Europe / Paris, et un commentaire qui cite le DevKit AI Makers for CYB et la licence Claude Code standard. Puis Save.
  9. Review Request, vérifie le récapitulatif, puis Submit Request.
  10. Attends la confirmation avant de te connecter. Tu peux suivre l’état de ta demande dans le menu Approvals ou My Requests.
  11. Dans VS Code, ouvre le panneau Claude Code (icône soleil dans la barre latérale).
  12. Choisis Claude.ai Subscription (compte Team ou Enterprise de la licence). Laisse de côté Anthropic Console et Bedrock / Foundry pour cette connexion.
  13. Quand VS Code demande d’ouvrir le site externe, clique Open.
  14. Sur la page Claude, connecte-toi avec le compte lié à la licence, puis Autoriser.
  15. Validation : le navigateur dit que tu peux fermer la fenêtre, et VS Code affiche le panneau Claude Code (checklist ou champ de prompt), sans bandeau de connexion bloquant.
Tip

Pas de licence perso en parallèle pour « débloquer » plus vite : on reste sur le parcours entreprise. Les captures de connexion montrent Claude.ai Subscription, pas un compte Console.

Microsoft Foundry (Azure) est la plateforme Microsoft pour accéder / brancher des modèles d’IA. Dans le DevKit, c’est ce qui te permet de donner un accès aux modèles IA pour l’agent que tu crées.

  1. Suis le guide détaillé interne : api-key.html (demande compte POC, ressource Foundry, déploiement modèle, récupération de la clé).
  2. Conserve la clé / l’endpoint dans un endroit sécurisé (pas dans le HTML public ni dans un chat).
  3. Validation : tu as les infos nécessaires pour brancher un modèle (voir le guide).
Guide détaillé

Pas de doublon ici : suivre le guide détaillé clé API Azure / Foundry.

Parallax est la plateforme interne self-service pour déployer des environnements cloud.

Dans le DevKit AI Makers for CYB, elle permet notamment :

  1. la création automatisée d’un dépôt de code sur l’instance GitLab interne Wavestone ;
  2. la création des ressources AWS pour héberger et exposer sur internet les pages web contenant les agents.

Portail : https://parallax.w-cyberlab.com/.

Tip

Garde cet onglet sous la main : les deux prochaines tâches se font entièrement dans Parallax.

Premier déploiement : provisionner l’environnement de développement (et le dépôt GitLab associé).

  1. Ouvre https://parallax.w-cyberlab.com/ et connecte-toi.
  2. Va dans l’onglet Templates.
  3. Déploie le template « Deploy development env ».
  4. Retourne dans l’onglet Accueil et surveille la création via le signal de statut sur la ligne de l’environnement.
  5. Validation : statut OK / dépôt créé.

1 / 5

Une fois le dépôt créé, tu déploies l’espace d’exposition (pages web prod + dév).

  1. Onglet Templates → section Lab → template « Dev - Build your AI agent here! ».
  2. Dans le formulaire : target env = l’environnement créé à l’étape précédente.
  3. Your website display name : le nom souhaité pour le site.
  4. site exposition : laisse le choix par défaut (accès avec authentification compte Wavestone).
  5. Lance le déploiement, retourne à Accueil, surveille le statut jusqu’à complétion.
  6. Clique Quick Connect et récupère : l’URL de la page web production, et l’URL de la seconde page (développement).
  7. Toujours via Quick Connect (ou le panneau secrets de la ligne), récupère aussi le Bot Token : c’est le secret que tu fourniras à Claude pour qu’il accède au dépôt de l’agent sur le GitLab interne Wavestone. Tu en auras besoin en tâche 4.1.
Rappel

Les deux pages sont protégées Wavestone : un SSO est nécessaire pour y accéder.

Sécurité

Ne commite jamais le Bot Token. Ne le colle pas dans un fichier du dépôt. Garde-le sous la main pour la tâche 4.1 : Connecter Claude au dépôt.

OK

URLs prod/dév + Bot Token récupérés = Macro 03 validé. Enchaîne sur la préparation de Claude.

1 / 9

Objectif : donner à Claude l’accès au dépôt GitLab de ton agent (URL + Bot Token récupérés en Macro 03).

  1. Sur Parallax, onglet Accueil.
  2. Sur la ligne de l’environnement, ouvre Quick Connect.
  3. Copie : le secret Bot Token, et l’URL du dépôt GitLab.
  4. Transmets-les à Claude via un prompt qui lui demande d’initialiser l’environnement de travail depuis le dépôt distant, avec les identifiants URL DU DÉPÔT + TOKEN D’ACCÈS.
  5. Validation : Claude a accès au dépôt (clone ou sync OK).
Exemple de prompt 
Initialise mon environnement de travail depuis le dépôt distant GitLab : <INDIQUER ICI L'URL DU DÉPÔT>. Je vais te donner un bot token pour que tu accèdes à GitLab. Utilise GCM pour que je te transmette le token. Ensuite, clone ou synchronise le dépôt, confirme-moi que l'accès est OK, puis résume brièvement la structure du projet.
Sécurité

Ne commite jamais le token. Ne le colle pas dans un fichier HTML du guide ni dans le dépôt. Remplace uniquement les placeholders dans le prompt chat Claude.

Par défaut, Parallax dépose dans chaque dépôt GitLab un fichier CLAUDE.md standardisé pour les AI Makers.

Ce fichier sert de brief permanent pour l’agent IA : conventions du DevKit, structure attendue, bonnes pratiques et contexte métier minimal. Claude le lit au début de chaque session et applique les standards Wavestone sans que tu aies à les réexpliquer.

  1. Depuis VS Code, demande à Claude de prendre connaissance de CLAUDE.md et de commencer le cadrage.
Exemple de prompt 
Lis le fichier CLAUDE.md à la racine du dépôt, résume-moi les points clés du brief, puis commence le cadrage de l’agent selon ces conventions.
Prêt

Ton environnement est prêt : tu peux commencer à vibecoder.

  1. En développant, dis à Claude « montre moi le résultat en dev » : ça enclenche la sync des modifications. Observe l’avancée sur la page de développement (tests / exploration) tout en gardant un agent fonctionnel en production.
  2. Quand tu es satisfait, dis à Claude « passe en prod » : sync vers la page de production (push / merge sur main).
