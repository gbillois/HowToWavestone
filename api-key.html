Tutoriel hands-on

Créer et utiliser une clé API Azure

Du compte POC à la première connexion réussie : suivez le parcours dans Azure Microsoft Foundry, cochez chaque étape et zoomez sur les captures d’écran.

# 100% navigateur # validation CDM requise # budget démo : 20 $ # Azure · Microsoft Foundry

Prérequis : demandez d’abord un compte POC dans Power Apps et attendez la validation de votre Chef de Mission (CDM). Pour la plupart des démonstrations, un budget de 20 $ suffit.

Le parcours

De la demande à la connexion testée

Le tutoriel couvre la création de la ressource Foundry, le déploiement d’un modèle et la récupération des trois informations nécessaires à votre application.

Compte POC→ Validation CDM→ Ressource Foundry→ Modèle déployé→ Connexion testée
Cas CrisisMaker & CyberBenchmark Helper

Si la clé sert à utiliser CrisisMaker ou CyberBenchmark Helper, ne créez pas de ressource vous-même : adressez-vous directement à l’équipe du produit, qui vous fournira l’accès adapté.

Commencer par la demande de compte POC

Ouvrir l’application Power Apps WavestonePower Apps ↗
ℹLa demande de compte POC et les opérations liées à l’accès Azure se font dans cette même application.
Phase 1 — Demander

Obtenir le compte POC et la validation

Cette phase précède toute action dans Azure.
0/2 étapes
1✓

Demander la création d’un compte POC

Dans l’application Azure Platform, sélectionnez Request the creation of a new POC account et complétez les informations demandées.
  1. Ouvrez l’application Power Apps.
  2. Sélectionnez Request the creation of a new POC account.
  3. Renseignez le besoin, les membres et le budget. Pour une démonstration standard, indiquez 20 $.
  4. Envoyez la demande pour validation.
Power Apps ↗
2✓

Attendre l’accord du CDM

La demande doit être approuvée par votre Chef de Mission. Une fois l’accord obtenu, ouvrez le portail Azure depuis le lien reçu par e-mail de l’équipe Azure Platform, ou directement depuis le portail.
portal.azure.com ↗
À retenir

Ne poursuivez pas tant que le compte POC n’est pas visible dans Azure et que l’approbation n’est pas confirmée.

Phase 2 — Créer

Créer la ressource Microsoft Foundry

Utilisez l’abonnement Self Service et la région West Europe.
0/4 étapes
1✓

Lancer la création d’une ressource

Dans l’accueil Azure, cliquez sur Create a resource.
2✓

Choisir Microsoft Foundry

Recherchez Microsoft Foundry, puis sélectionnez l’abonnement Self Service et le plan Microsoft Foundry.
3✓

Configurer la ressource et le projet

Renseignez les quatre champs structurants, puis lancez la revue de la configuration.
  1. Dans Resource group, choisissez le nom retenu lors de la demande du compte POC.
  2. Donnez un nom explicite à la ressource.
  3. Choisissez (Europe) West Europe.
  4. Donnez un nom au premier projet, puis cliquez sur Review + create.
4✓

Ouvrir le portail Foundry

Une fois le déploiement terminé, ouvrez la ressource puis cliquez sur Go to Foundry portal.
Phase 3 — Déployer

Déployer un modèle et récupérer la clé

La clé devient utilisable une fois un modèle déployé.
0/5 étapes
1✓

Afficher les déploiements

Dans la nouvelle interface Foundry, cliquez sur View deployments dans la carte Use a model.
2✓

Déployer un modèle de base

Dans Models → Deployments, cliquez sur Deploy a base model.
3✓

Rechercher le modèle

Recherchez le modèle souhaité — par exemple gpt-5.5 dans le tutoriel — puis ouvrez sa fiche.
Note

La disponibilité des modèles dépend de votre abonnement et de la région. Si gpt-5.5 n’est pas proposé, choisissez un modèle autorisé pour votre projet.

4✓

Déployer avec les paramètres par défaut

Cliquez sur Deploy, puis sur Default settings.
5✓

Récupérer les informations de connexion

Une fois le déploiement créé, ouvrez l’onglet Details. Copiez les trois valeurs dont votre application aura besoin.
EndpointPour certaines applications, conservez uniquement la base de l’URL, par exemple https://mve-ai.services.ai.azure.com.
KeyC’est votre clé API. Ne la partagez jamais et stockez-la comme un secret.
NameC’est le nom du déploiement, par exemple gpt-5.5.
Phase 4 — Tester

Vérifier la clé dans DeckSeeder

Exemple d’intégration avec une application qui utilise Azure OpenAI.
0/3 étapes
1✓

Ouvrir la configuration IA

Ouvrez DeckSeeder et cliquez sur Configure AI.
deckseeder.pages.dev ↗
2✓

Renseigner les paramètres Azure

Choisissez Azure OpenAI comme fournisseur, puis collez la clé, l’endpoint et le nom du déploiement. Sélectionnez enfin le modèle correspondant.
Sécurité

Vérifiez que l’usage de l’IA est autorisé pour le contenu manipulé. Ne saisissez jamais une clé dans une application que vous ne connaissez pas ou qui ne protège pas les secrets.

3✓

Tester puis enregistrer

Cliquez sur Test connection. Si le voyant passe au vert et que le statut Connected apparaît, cliquez sur Save.
Bravo

Votre ressource, votre modèle et votre clé sont opérationnels. Vous pouvez maintenant connecter une application compatible à ce déploiement.

Sécurité

Traitez la clé comme un mot de passe

Toute personne qui possède la clé peut consommer le quota et les services associés. Appliquez ces règles dès sa création.

Les quatre réflexes
  • Ne partagez jamais la clé en clair dans un e-mail, un chat ou un ticket, et ne la commitez jamais dans GitHub.
  • Stockez-la dans un gestionnaire de secrets ou un coffre-fort de mots de passe, pas dans un fichier ou des notes en clair.
  • Dans le code, utilisez une variable d’environnement ou un fichier .env exclu du dépôt via .gitignore.
  • En cas de fuite suspectée, révoquez immédiatement la clé et générez-en une nouvelle.
